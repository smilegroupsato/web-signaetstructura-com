同じドルを二度働かせるDeFi――TwofoldとDualPool型資本再利用

同じ元本をidle時はlending、swap時はLPへ。Twofoldは「高利回りprotocol」ではなく、deploy直後のcapital-reuse primitiveとして読む。

Research as of: 2026-08-31Updated: 2026-08-31Risk level: HighPublication ID: scmr-20260831-002

TwofoldはRobinhood Chain上でUniswap v4のDualPool hookを利用し、LP資本のUSDG側を取引がない時間はMorpho系vaultへ置き、swapが来た瞬間だけ流動性として引き出す構造を実装している。従来「lendingに置くか、LPに置くか」の二者択一だった資本を、時間軸で切り替えて二つのcash flowへ接続する設計だ。

同じ資本を、時間で二つの市場へ接続する

ここで起きているのは二重計上ではない。同じ元本が、平時にはERC-4626 vaultでlending yieldを得て、swap時だけJIT withdrawalされ、Uniswap v4のLPとしてfeeを受け取り、その後vaultへ戻る。

Deploymentは確認できた。ただし旧ページが残っている

現行Twofold docsはRobinhood Chain（chain id 4663）のDualPoolHook、Factory、Registry、StakingVault、TWO token等のcontract addressを公開し、Registryに19 listingsがあると明記している。TWO token contractにも実トランザクションが確認できる。一方、旧stats pageには「contracts are not yet deployed」というlaunch前文言が残る。したがってWeb UIの一画面だけでdeploymentを判断せず、現行docs・Registry・explorer evidenceを優先する。

Pool TVLとfee実績は、同じ強さでは確認できない

Twofoldの現行docsは各poolが0.30% swap feeを設定すると説明するが、「pair volume, 24h」はTwofold固有poolのvolumeではなく、Robinhood Chain上の全Uniswap v4 poolにおける当該pair volumeだと注意している。これをTwofoldのfee実績へ直接掛け算してはいけない。今回のReviewではTwofold固有aggregate Pool TVL、Twofold-only swap volume、realized LP feeを独立に固定できていない。

Key finding

確認できたのは「contracts / Registry / deposits open」というdeployment evidenceまで。Twofoldを実績ある高yield protocolとして扱うEvidenceはまだない。

TWOのrevenue routingは「実収益が既に出ている」とは言えない

TwofoldはTWOをfixed 1B supply、no mint、no ownerと説明し、StakingVault経由でprotocol revenueをreal assetsとして配る設計を掲げる。しかし現行docsは、poolsはliveでもharvestはまだ一度も行われず、protocol revenueは0だと明記している。将来のfee-routing設計と現在の実績を混同しない。

Audit / contract risk

DualPool hookについてTwofoldはUniswapがauditしたupstream bytecodeをbyte-for-byte unmodifiedでdeployしたと説明する。一方、Twofold固有wrapper contractsについて第三者audit済みとは確認できない。「Uniswapがauditした」をTwofold全体のaudit済みへ読み替えるべきではない。

Capital parkingの次に何が生えるか

Twofoldの意味は単独protocolより、Robinhood Chainの資本形成の第二段階として見た方が分かりやすい。stablecoinとlending layerが先に厚くなり、その既存vaultを部品としてcapital-reuse primitiveが生える。

What would falsify this view?

今後、on-chain aggregate TVLやrealized harvest dataが公開され、docsの説明と一致しなければ評価を改訂する。swap volumeが小さく追加feeがほぼ生まれない場合、capital-reuseの経済的優位性も弱まる。wrapper contractsのriskが顕在化すれば、upstream auditの価値だけでは安全性を支えられない。

Evidence / Sources

Twofold current Docs / App / Home、legacy Stats、Robinhood Chain explorer evidence、Morpho Robinhood Chain Network Data、Uniswap DualPool upstream design / audit referencesを参照。contract addressは現行docsで固定したが、wrapper各contractのdeployment block/dateは今回独立には固定していない。

Limitations

Twofold固有aggregate Pool TVL、Twofold-only swap volume、realized fee、harvest実績を独立に固定できていない。docs掲載pair volumeはchain上全Uniswap v4 poolのpair volumeでありTwofold revenueではない。wrapper contractsの第三者auditも確認できていない。
