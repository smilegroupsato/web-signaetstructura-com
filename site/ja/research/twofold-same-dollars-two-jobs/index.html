同じドルを二度働かせるDeFi――TwofoldとDualPool型資本再利用

Research as of: 2026-08-31Updated: 2026-09-01Risk level: HighPublication ID: scmr-20260831-002

要約

TwofoldはRobinhood Chain上でUniswap v4のDualPool hookを利用し、LP資本のうちUSDG側を、取引がない時間はMorpho系Vaultへ預け、スワップが来た瞬間だけ流動性として引き出す構造を実装している。従来は「貸出に回すか、LPとして置くか」の二者択一だった資本を、同時に二重利用するのではなく、時間に応じて役割を切り替えることで、借り手が支払う金利とスワップ手数料の双方につなぐ仕組みである。

2026-08-31時点では、現行Twofold docsがRobinhood Chain（chain id 4663）のDualPoolHook、Factory、Registry、StakingVault、TWO token等のコントラクトアドレスを公開し、Registryに19件の登録があると明記している。TWO token contractにも実際のトランザクションが確認できる。したがって、初稿で懸念した「まだデプロイされていないのではないか」という問題は、旧stats.htmlにローンチ前の文言が残っていることによるサイト内の情報不整合と見るのが妥当である。

ただし、公開時点で確認できるのは、コントラクトやRegistryが存在し、預入受付が開始されているというデプロイの証拠までである。Twofold固有のプール総TVL、Twofoldのプールだけで発生したスワップ出来高、実現したLP手数料、収益回収（harvest）の実績は別問題だ。現行docs自身が、まだharvestは一度も行われておらず、プロトコル収益は0だと明記している。よって本稿は高利回りの実績紹介ではなく、資本再利用という新しい金融部品が稼働し始めた初期段階の研究として読むべきである。

1. 同じ資本を、時間で二つの市場へ接続する

DualPool型の資本サイクルは単純である。

LP資本は平時、許可リストに登録されたERC-4626 Vaultへ置かれる。スワップが発生すると、hookが必要な資本を同一トランザクション内で引き出し、Uniswap v4上で取引を成立させる。そこで手数料を得た後、残った資本をVaultへ戻す。

「同じドルを二重計上する」のではない。同じ元本が時間によって役割を切り替える。

  • 待機時：貸出・Vaultの利回りを得る
  • スワップ時：LP手数料を得る
  • スワップ後：Vaultへ戻る

この違いは重要である。Tomb型のように新しいtokenの発行を主な原資としてAPRを作るのではなく、設計上の収益源は外部の借入金利と取引手数料である。

2. デプロイは確認できた。ただし旧ページが残っている

現行docsはchain id 4663上の主要コントラクトを以下のように公開している。

  • DualPoolHook: 0x127B3f3b7769f659C5eDBfF8b4005443f19FAAc0
  • AllowlistedFactory: 0x92cbCe5d1f5b7018b98bE81a8B9d010B547F0c85
  • OperatorController: 0xc7295643EC5414DE243e3F9810Eb28F85e5d9ABb
  • VaultAllowlist: 0xe44C0d41A1aFbF7234492bb7a3F745246c351C42
  • Registry: 0x1b66DD14C9281A18E696dbdb40cFB5070842c0C2
  • StakingVault: 0x06E463fDa4BEb4aA096142E673240aB9719fB3A9
  • TWO token: 0x2A4a33A2163D005d8E7f1D9aC08d14c98db288d5
  • underlying Steakhouse USDG vault: 0xBeEff033F34C046626B8D0A041844C5d1A5409dd

現行docsは19件のプール／登録と、預入受付中であることを明記する。TWO contractはexplorerで検証済みコントラクトとして表示され、多数のtransaction / Transfer / Approval eventsが存在する。

一方、stats.htmlには依然として「contracts are not yet deployed」というローンチ前の文言が残る。この不整合は隠すべきではない。現行docs・appと旧stats pageで更新状態が一致していないため、読者はWeb UIの一画面だけを見てデプロイ済みかどうかを判断すべきではない。

本稿では、現行のコントラクトRegistryとexplorer上の証拠を優先する。

3. プールTVLと手数料実績は、同じ強さでは確認できない

Twofoldの現行home/appは、Registryから19件のプールを読み込むと説明し、各プールが0.30%のスワップ手数料を設定しているとする。一方、画面に表示される「pair volume, 24h」はTwofold固有プールの出来高ではなく、Robinhood Chain上の全Uniswap v4プールにおける当該ペアの出来高だとdocs自身が注意している。

したがって、その数字に0.30%を掛けてTwofoldの手数料収入とみなすことはできない。

さらに、旧Statsのプール総TVL欄は空のままであり、今回のResearch ReviewではTwofold固有の総TVLを独立に固定できなかった。第三者が示すTWO tokenの流動性や出来高も、DualPool LPのTVLとは別物である。

事実として固定できるのは次までである。

  • コントラクトが公開されている。
  • Registryに19件の登録があると現行docs/appが示している。
  • 預入受付中と明記されている。
  • 基礎となるSteakhouse USDG vaultはMorpho上で実在し、大型資本を保有する。
  • Twofold固有のプール総TVL、実現したスワップ手数料、harvestによるプロトコル収益は、今回独立に固定できていない。

4. TWOの収益分配は「すでに実収益が出ている」とは言えない

TwofoldはTWOについて、発行上限10億枚、追加発行なし、ownerなしと説明し、StakingVaultを通じてプロトコル収益をUSDGやUSDC等の実資産で分配する設計を掲げている。

しかし、現行docsは同時に重要な留保を書いている。

pools are live, but no harvest has happened and the protocol has earned nothing from them.

将来harvestが行われた場合、プロトコルはプール利益、すなわちVault利回りと取得原価を上回る取引手数料の合計から最大20%を受け取れる。LP元本は対象外とされる。

したがって現時点で、「TWOのステーキングはプロトコルの実収益を継続的に配当している」と表現するのは早い。ステーキング画面に表示される報酬やローンチ時に用意された報酬と、実際にharvestされたプロトコル収益は分けて考えなければならない。

5. 監査とコントラクトのリスク

DualPool hookについて、Twofoldは、Uniswapが監査した上流実装のbytecodeを一切変更せず、そのままデプロイしたと説明する。一方、Twofold独自のwrapper contractsはオープンソースで、Slither、Aderyn、Halmos、Mythril等による静的解析、形式検証、mutation testingを実施したとするものの、第三者監査済みとは確認できない。

したがって、リスクは二層に分けて考える必要がある。

  1. 上流のDualPool中核部分に由来するリスク
  2. Twofold独自のwrapper / Registry / Controller / VaultAllowlist / StakingVault等に由来するリスク

「Uniswapが監査した」という事実を、Twofold全体が第三者監査済みであるという意味に読み替えてはいけない。

6. 「資本の滞留」の次に何が生えるか

Twofoldが面白いのは、単独のプロトコルとしてより、Robinhood Chainで資本形成が進んだ後に現れた第二段階の仕組みとしてである。

2026-08-31取得のMorpho Robinhood Chain dataでは、総預入額約9.21億ドル、稼働中の貸出残高約4.08億ドル、TVL約5.12億ドル。ステーブルコインと貸出基盤が先に厚くなり、その既存Vaultを部品として、資本を再利用する新しいプロトコルが生まれている。

概念的には、

新しいチェーン → ステーブルコイン流入 → 貸出基盤 → 利回りを生むVault → 資本再利用型プロトコル

という流れである。これは、既存の金融部品を組み合わせて新しい商品を作る「Composition Boom」の一例になり得る。

前提・限界・反証条件

  • DualPoolHook等のコントラクトアドレスは現行docsで固定したが、wrapper群の個別deployment block/dateは今回独立に固定できていない。
  • Twofold固有のプール総TVL、Twofoldプールだけのスワップ出来高、実現手数料、harvest回数は独立に固定できていない。
  • docs掲載のpair-volumeはchain上全Uniswap v4プールのpair volumeであり、Twofoldの収益ではない。
  • 現行docsによれば、harvestによるプロトコル収益はまだ0。将来の収益分配設計と実績を混同しない。
  • wrapper contractsについて第三者監査を確認できていない。
  • 貸出利回りとスワップ手数料を重ねた追加収益が、smart-contract、LP、depeg、market-hours等の追加リスクを上回るとは限らない。
  • 今後on-chain aggregate TVL / realized harvest dataが公開され、docsの説明と一致しなければ本稿の評価を改訂する。
